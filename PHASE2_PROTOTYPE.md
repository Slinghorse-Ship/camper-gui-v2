# Phase 2 minimal prototype

## Compatibility baseline

- Venus OS device: `v3.80~39`, build `20260716174100`
- Installed native and WASM gui-v2 package: `1.3.14-r0`
- Source baseline: public gui-v2 tag `v1.3.14`, commit `c8f5a14353d1c6dc7554cbc8bf5d167af8fd00d7`
- Device Qt version: `6.8.3`
- Primary display: GX Touch 50, native resolution `800x480`

The compatibility evidence and upstream baseline are recorded in `PORT_BASELINE.md`.

## Implemented scope

The prototype keeps `Main.qml` and `ApplicationContent.qml` unchanged. A full-screen
`CamperShell` is hosted at the top of the existing `MainView`. The standard Victron
pages, models, cards, settings, dialogs and notification layers remain present.

- The initial daily view is `pages/camper/CamperHome.qml`.
- `EINST.` selects the existing `SettingsPage.qml` through the existing
  `NavBar.setCurrentPage()` contract and hides the Camper layer.
- The Ford `X` behavior hides the Camper layer and exposes the preserved Victron UI.
- A small `CAMPER` return control is shown over the Victron UI while the Camper layer
  is hidden.
- A full-screen pointer grabber prevents touches in empty Camper areas from reaching
  the Victron pages below it.
- The logical UI remains exactly `800x480` on GX Touch 50. `CamperViewport` applies
  uniform, centered scaling only when another display or browser size requires it.

## Native gui-v2 data used

`data/camper/CamperVictronAdapter.qml` consumes existing gui-v2 model properties and
does not create parallel transport or duplicate service paths:

| Camper field | Existing gui-v2 source | Existing model implementation |
| --- | --- | --- |
| Connection state | `Global.backendReady` | `BackendConnection.state` |
| Battery SOC | `Global.system.battery.stateOfCharge` | `ActiveSystemBattery`, system service `/Dc/Battery/Soc` |
| Battery voltage | `Global.system.battery.voltage` | `ActiveSystemBattery`, system service `/Dc/Battery/Voltage` |
| Total solar power | `Global.system.solar.power` | `System.solar`, combining its existing AC/DC PV models |

The same `Global.system` abstraction is populated by the normal D-Bus backend on GX
and by the normal MQTT backend in WASM.

## Intentionally not connected in Phase 2

No interface was guessed for these fields or controls:

- freshwater level and remaining litres
- Ruuvi/interior temperatures
- Autoterm state and commands
- MaxxFan state and commands
- water-pump state and command
- MultiPlus command and home-card output value
- STAR-Power lights and dimming

Their source-shaped controls remain visible but disabled and are labelled as not yet
connected. Phase 4 must bind them through documented native services where available,
or through a dedicated Node-RED/custom-device adapter where no native Victron model
exists.

## Visual sources

The Phase-2 geometry is taken from the current Ford SYNC v3.9.9
`CamperMain.qml`/`ModernShell.qml` implementation. Reusable visual primitives were
ported from `LineIcon.qml`, `ModernTile.qml` and `TouchButton.qml`; the Ford-only
`AL2HMIBridge` import was removed.

Design note from the owner: the older
`reference/CamperControl_SYNC3_Dark_Light_Mockup.png` logo, line icons and visual
language are preferred. Before broad Phase-3 page work, freeze whether that preference
changes only the logo/icon set or the complete page layout. The adapter and page-host
architecture does not depend on that decision.

## Verification performed

- All new and changed QML files parsed successfully with Qt `6.8.3` `qmlformat`.
- The standalone Camper Home tree passed Qt `6.8.3` `qmllint`.
- The exact `800x480` Home rendered offscreen with Qt `6.8.3` without QML load errors.
- Automated pointer clicks passed for `EINST.`, `X`, `HOME`, `LICHT` and `12/230`.
- A read-only live Cerbo check returned numeric values for all three upstream system
  paths used by the adapter (battery SOC, battery voltage and DC PV power).
- `git diff --check` passed before the prototype commit.

The visual check is generated by `tools/camper-preview/render.py`; touch targets are
checked by `tools/camper-preview/smoke_test.py`.

## Build status

The official `scripts/build-gx.sh` and `scripts/build-wasm.sh` have not yet been run on
this Windows host. WSL is not installed, and the host has neither the Venus GX SDK nor
the Emscripten/Qt WASM SDK. The locally installed PySide package supplies the exact Qt
parser/runtime but not Qt CMake development files or either cross-compilation SDK.

No file has been deployed to or replaced on the Cerbo.
